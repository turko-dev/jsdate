# jsdate

![jsdate banner](https://placehold.co/1200x300/1c1c1e/22c55e?text=jsdate)

**jsdate** is a Python package that mirrors much of JavaScript's `Date` API, including constructor forms, getters, setters, and string conversion methods. It is designed to feel familiar to JavaScript developers while using idiomatic Python under the hood.

## Features

jsdate implements a JavaScript-like `Date` class with:

- **Constructor forms** matching JavaScript's `new Date()` patterns:
  - No arguments → current local time
  - Timestamp in milliseconds → date from epoch
  - ISO 8601 UTC string (`YYYY-MM-DDTHH:mm:ss.sssZ`)
  - Copy-construction from another `Date` instance
  - Component-based construction `(year, monthIndex, day?, hour?, minute?, second?, millisecond?)` with overflow/underflow behavior
- **Static methods:**
  - `Date.now()` → current timestamp in milliseconds
  - `Date.parse(dateString)` → parse supported date strings to timestamps
  - `Date.UTC(...)` → build a UTC timestamp from components
- **Getter methods:**
  - Local-time getters: `getFullYear()`, `getMonth()`, `getDate()`, `getDay()`, `getHours()`, `getMinutes()`, `getSeconds()`, `getMilliseconds()`, `getTimezoneOffset()`, `getYear()` (deprecated)
  - UTC getters: `getUTCFullYear()`, `getUTCMonth()`, `getUTCDate()`, `getUTCDay()`, `getUTCHours()`, `getUTCMinutes()`, `getUTCSeconds()`, `getUTCMilliseconds()`
  - `getTime()` / `valueOf()` → Unix timestamp in milliseconds
- **Setter methods:**
  - Local-time setters: `setFullYear()`, `setMonth()`, `setDate()`, `setHours()`, `setMinutes()`, `setSeconds()`, `setMilliseconds()`, `setTime()`, `setYear()` (deprecated)
  - UTC setters: `setUTCFullYear()`, `setUTCMonth()`, `setUTCDate()`, `setUTCHours()`, `setUTCMinutes()`, `setUTCSeconds()`, `setUTCMilliseconds()`
- **Formatter methods:**
  - `toDateString()`, `toTimeString()`, `toString()`
  - `toISOString()`, `toJSON()`, `toUTCString()`, `toGMTString()` (deprecated alias)
  - `toLocaleDateString()`, `toLocaleTimeString()`, `toLocaleString()` (locale-aware via Python's `strftime`)
- **Python integration:**
  - `__str__()` → human-readable string
  - `__int__()` → timestamp as integer
  - `to_datetime()` → underlying `datetime` object
  - Full type hints and docstrings for IntelliSense

## Usage

```python
from jsdate import Date

# Current time
now = Date()
print(now.getFullYear())

# From timestamp
epoch = Date(0)
print(epoch.toISOString())  # 1970-01-01T00:00:00.000Z

# From ISO string
d = Date("2024-08-21T14:30:45.123Z")
print(d.toDateString())
print(d.toTimeString())

# Component constructor (JavaScript-style month indexing)
d2 = Date(2024, 7, 21, 14, 30, 45, 123)  # monthIndex 7 = August
print(d2.toISOString())

# Setters with overflow
d.setMonth(12)  # rolls into next year
d.setDate(32)   # rolls into next month
d.setHours(25)  # rolls into next day

# Static utilities
ts = Date.now()
parsed = Date.parse("2024-08-21T14:30:45.123Z")
utc_ts = Date.UTC(2024, 7, 21, 14, 30, 45, 123)
```

## Limitations

- **Locale methods:** `toLocaleDateString()`, `toLocaleTimeString()`, and `toLocaleString()` delegate to Python's `strftime` and depend on the host environment's locale settings. They are approximations of JavaScript's `Intl.DateTimeFormat`-backed methods.
- **Parsing:** `Date.parse()` supports a limited subset of date formats compared to JavaScript engines. It handles ISO 8601 forms and some common RFC-style strings, but is not a full drop-in replacement for browser or Node.js parsing behavior.
- **Timezone handling:** Local-time operations use the system's local timezone via Python's `astimezone()`. Behavior may differ across platforms and timezone configurations.
